# 多 Activity 拆分重构方案

## 目标
把当前单 Activity（MainActivity 承载 6 个 Screen 用 Compose 状态切换）拆成 6 个独立 Activity，每个 Activity 独立 ViewModel，跨页数据用 Intent extras 传递。返回键由系统 Activity 栈天然处理，彻底解决 MIUI 上 `BackHandler` 不触发导致退出应用的问题。

## 拆分后的 Activity 结构

```
SplashActivity → IntroActivity → RoleSelectionActivity（入口）
                                    ├─→ CollectorActivity
                                    └─→ ClientListActivity
                                          └─→ ViewerActivity
                                                └─→ RecordingLibraryActivity
                                                      └─→ RecordingPlaybackActivity
```

返回栈靠系统 Activity 栈：每层 `startActivity` 后不 `finish`（除 RoleSelection 选完角色后 finish 自己），按返回键逐级回退。

### 每个 Activity 的职责

| Activity | 作用 | VM | Intent extras 入参 | 启动方 |
|---|---|---|---|---|
| **RoleSelectionActivity** | 选角色 | 自己的轻量 VM（无状态，纯 UI） | 无 | Splash/Intro |
| **CollectorActivity** | 采集端预览+状态 | CollectorViewModel | 无 | RoleSelection（选 Collector 后 finish RoleSelection） |
| **ClientListActivity** | 扫描+设备列表 | ClientListViewModel | 无 | RoleSelection（选 Client 后 finish RoleSelection） |
| **ViewerActivity** | 实时观看 | ViewerViewModel | `device: CollectorDevice`（Parcelable） | ClientList |
| **RecordingLibraryActivity** | 录像列表 | RecordingLibraryViewModel | `device: CollectorDevice`（Parcelable） | Viewer |
| **RecordingPlaybackActivity** | 播放 | RecordingPlaybackViewModel | `device: CollectorDevice` + `fileId: String` | RecordingLibrary |

### Intent extras 数据传递

**`CollectorDevice` 改为 `Parcelable`**（用 `@Parcelize`，需加 `kotlin-parcelize` 插件）：
- ClientList → Viewer：传选中的 device
- Viewer → RecordingLibrary：传同一 device（录像库需要 device.hostAddress/tcpPort 查询采集端）
- RecordingLibrary → RecordingPlayback：传 device + fileId

**不再需要跨页共享 `viewer.selectedDevice`**--RecordingLibrary/Playback 直接从 Intent 拿 device。

## ViewModel 拆分

把现有 `HomeCameraViewModel`（664 行）按 Screen 拆成多个独立 VM，各自只持有自己页面的状态：

### 1. `CollectorViewModel`（AndroidViewModel）
- 持有：`collectorState: CollectorState`（serviceStatus/connectedClientCount/recordingStatus/errorMessage）
- 方法：`startCollectorService()`、`stopCollectorService()`、`setDisplayRotationDegrees()`
- 保留：`serviceStatusReceiver` 广播接收器（监听 ForegroundService 状态）
- `onCleared`：unregisterReceiver（**不停 Service**--Service 由用户退出时显式停）

### 2. `ClientListViewModel`（AndroidViewModel）
- 持有：`clientState: ClientState`（scanStatus/devices）
- 方法：`scanCollectors()`、`cancelScan()`
- `onCleared`：cancelScan、shutdown scannerExecutor

### 3. `ViewerViewModel`（AndroidViewModel）
- 持有：`viewerState: ViewerState`（status/errorMessage）、`viewerConnectionState`
- 方法：`connectViewer(device)`、`onViewerSurfaceReady/Destroyed()`、重连逻辑
- 保留：viewerSurface/viewerConnection/viewerStreamKey/viewerGeneration 内部状态
- `onCleared`：stop viewer、releaseWifiLock、shutdown viewerExecutor
- 进入时从 Intent 拿 device 自动连接；`onResume` 时若连接断开则重连

### 4. `RecordingLibraryViewModel`（AndroidViewModel）
- 持有：`recordingLibraryState: RecordingLibraryState`
- 方法：`loadRecordingDates()`、`loadRecordingFiles(date)`、`downloadRecordingToGallery(fileId)`
- 从 Intent 拿 device 作为查询目标
- `onCleared`：shutdown recordingExecutor

### 5. `RecordingPlaybackViewModel`（AndroidViewModel）
- 持有：`recordingPlaybackState: RecordingPlaybackState`
- 方法：`loadRecordingForPlayback(fileId)`、`savePlaybackToGallery()`
- 从 Intent 拿 device + fileId
- `onCleared`：shutdown recordingExecutor

### 6. `RoleSelectionActivity`
- 无 VM（纯 UI，点按钮 startActivity）

## 关键改动点

### 1. `CollectorDevice` 改 Parcelable
```kotlin
@Parcelize
data class CollectorDevice(
    val deviceId: String,
    val name: String,
    val hostAddress: String,
    val tcpPort: Int,
    val online: Boolean,
) : Parcelable
```
加 `kotlin-parcelize` 插件到 `app/build.gradle.kts`。

### 2. `HomeCameraState.kt` 拆分
- `Screen` 枚举删除（不再需要状态机切屏）
- `HomeCameraState`/`HomeCameraAction`/`HomeCameraReducer` 拆成各 VM 自己的 state/action（或保留各子状态类，去掉统一的容器）
- `RecordingEntry` 已是 data class，转 Parcelable 或在 Intent 里传 fileId 字符串

### 3. 删除 `HomeCameraApp.kt` 的统一路由
- 删除 `HomeCameraApp` Composable 的 `when(state.screen)` 路由和 `BackHandler`
- 各 Screen Composable 保留，但 `@Composable` 入口函数移到各自 Activity 的 `setContent` 里
- 共用的 `AppTopBar`/`StatusRow`/`StatusDot`/`PillButton` 等 helper 保留在公共文件（如 `ui/CommonComponents.kt`）

### 4. 删除 `MainActivity.kt`
- 不再需要统一的 MainActivity
- 其中的权限请求、`ensureCollectorPermissionsAndStart`、`finishAndRemoveTask` 逻辑分散到 CollectorActivity（权限）和各 Activity（退出）
- `enableEdgeToEdge`/沉浸式在每个 Activity 自己管理

### 5. `AndroidManifest.xml` 注册 6 个 Activity
- RoleSelectionActivity 设为 `exported="false"`（Splash/Intro 启动它）
- 都保留 `screenOrientation="portrait"` + `configChanges`
- ViewerActivity 和 RecordingPlaybackActivity 在各自 Activity 里管理沉浸式（`onCreate`/`onResume` 隐藏系统栏，`onPause` 恢复）

### 6. Splash/Intro 改启动 RoleSelectionActivity
- `SplashActivity.navigateToNextScreen()` 和 `IntroActivity.onAgree` 把 `MainActivity::class.java` 改成 `RoleSelectionActivity::class.java`

### 7. `CollectorCameraRuntime` 单例保留
- 不受影响，CollectorActivity 继续用 `setPreviewSurface`/`setPreselectedPreviewSize` 等
- `attachStreamer`/`detachStreamer` 由 ForegroundService 调用，跨 Activity 共享 streamer

### 8. 退出 App 语义
- RoleSelectionActivity 是返回栈底，按返回键退出 App（系统默认行为）
- CollectorActivity 退出时 `stopCollectorService()` + `finish()`
- 其他 Activity 退出时 `finish()`（VM `onCleared` 清理各自资源）

## 保留不变的部分
- `CollectorForegroundService` 及其 TCP/UDP 协议
- `CameraH264Streamer`/`Mp4SegmentRecorder`/`AacAudioStreamer` 采集端逻辑
- `H264UdpViewer`/`LanViewerConnector` 客户端观看逻辑
- `RecordingApiClient`/`RecordingTransferServer` 录像下载逻辑
- `ControlProtocol`/`RecordingLibrary`/存储清理逻辑
- 所有单元测试（`ControlProtocolTest`/`RecordingLibraryTest`/`Mp4SegmentRecorderTest` 等纯逻辑测试不受影响）

## 实施步骤（分 4 步，每步可编译验证）

### 步骤1：基础设施
- `app/build.gradle.kts` 加 `kotlin-parcelize` 插件
- `CollectorDevice` 改 `@Parcelize Parcelable`
- 新建 `ui/CommonComponents.kt`，把 `AppTopBar`/`StatusRow`/`StatusDot`/`PillButton`/`ScanRefreshButton` 等共用组件从 `HomeCameraApp.kt` 抽出
- 编译验证

### 步骤2：拆 VM
- 新建 `CollectorViewModel`/`ClientListViewModel`/`ViewerViewModel`/`RecordingLibraryViewModel`/`RecordingPlaybackViewModel`
- 从 `HomeCameraViewModel` 按职责拆分代码到各 VM
- 保留 `HomeCameraState.kt` 里的子状态类（CollectorState/ClientState/ViewerState/RecordingLibraryState/RecordingPlaybackState），删掉 `HomeCameraState` 容器、`Screen` 枚举、统一 `HomeCameraAction`/`HomeCameraReducer`
- 编译验证（此时 `HomeCameraApp.kt`/`MainActivity.kt` 暂时编译不过，下一步修）

### 步骤3：拆 Activity
- 新建 6 个 Activity 文件（`ui/activity/` 下）
- 每个 Activity `setContent` 调用对应的 Screen Composable
- `HomeCameraApp.kt` 拆掉统一路由，各 Screen Composable 改为独立公开函数
- 删除 `MainActivity.kt` 和 `HomeCameraApp` Composable
- 更新 `AndroidManifest.xml` 注册新 Activity
- Splash/Intro 改启动 `RoleSelectionActivity`
- 编译验证

### 步骤4：沉浸式 + 收尾
- ViewerActivity/RecordingPlaybackActivity 管理沉浸式系统栏
- CollectorActivity 处理权限请求 + Service 启停
- 各 Activity 的 `onConfigurationChanged` 同步旋转度数
- 编译 + 单测验证
- 实机安装测试返回键

## 风险与权衡
1. **Viewer 重连代价**：从录像库返回观看页会重连（你已确认可接受），短暂黑屏后恢复。
2. **改动量大**：涉及 ~15 个文件的增删改，但都是机械性拆分，逻辑不变。
3. **`@Parcelize` 依赖**：需加插件，但这是 Android 官方方案，无风险。
4. **状态隔离更彻底**：各页 VM 独立，不再有跨页隐式依赖，长期可维护性更好。
5. **返回键可靠性**：系统 Activity 栈在所有 ROM 上行为一致，彻底绕过 `BackHandler`/预测返回的兼容性问题。
