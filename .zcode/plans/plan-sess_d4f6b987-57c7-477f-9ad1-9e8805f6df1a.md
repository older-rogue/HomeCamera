# 历史录像首帧预览缩略图（两列正方形网格）

## 目标
历史录像列表改成**两列网格**，每格顶部是**大正方形首帧预览**，下方是时间/大小/按钮。损坏/录制中/旧采集端无缩略图时显示占位，不崩溃。

## 方案总览（懒加载 + 复用现有 HTTP 服务器，零协议/录制路径改动）

录制端已有 `RecordingHttpServer`（端口 62003，支持 `GET /<fileId>` 与 Range、带路径穿越防护）。查看端已用 `http://<host>:62003/<fileId>` 拉流播放。本方案新增 `?thumb=1` 查询路由：录制端收到该请求时，用 `MediaMetadataRetriever` 抽首帧、按 muxer 旋转校正、压成小 JPEG 返回；结果以 `(fileId, sizeBytes)` 为键内存缓存（复刻 `RecordingIntegrityChecker` 的缓存范式）。查看端用单例 `ThumbnailLoader`（LruCache + 2 线程 + 并发去重）拉取解码，通过 ViewModel 的 `state.thumbnails`（仿 `downloads` map）驱动网格重组。

为什么懒加载而非录制时生成：①对**历史已有录像**立即生效；②不动录制热路径；③零协议改动；④仅对滚入视野的格子付费，天然懒。

## 改动清单（6 个文件，1 个新建采集端类 + 1 个新建查看端类）

### 1. 新建 `app/src/main/java/com/zx/homecamera/core/storage/ThumbnailGenerator.kt`（采集端）
采集端首帧 JPEG 生成器，结构对齐 `RecordingIntegrityChecker`：
- `ConcurrentHashMap<String, CachedThumb>`，键 fileId，值 `(sizeBytes, jpegBytes)`；大小变化时重生成。
- `thumbnailBytes(fileId, file): ByteArray?`：命中缓存直返；否则取 per-fileId 锁，`MediaMetadataRetriever.setDataSource` -> 读 `METADATA_KEY_VIDEO_ROTATION` -> `getFrameAtTime(0, OPTION_CLOSEST_SYNC)`（关键帧对齐，最快，即"首帧"）-> `Matrix.postRotate` 校正 -> `createScaledBitmap` 限宽 **320**（流默认 640×480，2 倍下采样，正方形 ~159dp 预览足够清晰且 JPEG 仍小）-> `compress(JPEG, 80)`。异常/损坏返回 null。
- per-fileId `lock` 对象做生成去重。
- `clear()` 清缓存（采集端停止时可选调用）。
- `CachedThumb` 用普通 class 而非 data class，避免 `ByteArray` equals 警告。

### 2. 改 `app/src/main/java/com/zx/homecamera/service/RecordingHttpServer.kt`（采集端）
- 新增字段 `private val thumbnailGenerator = ThumbnailGenerator()`（服务器自持，无需改 `CollectorForegroundService` 接线）。
- `handleConnection` 中：分离 `rawPath` 的路径与查询串；`isThumb = query` 含 `thumb=1`；用 `resolveSafeFile(pathPart)` 复用现有路径安全校验解析 mp4 File。
- 分支：`isThumb` -> `serveThumbnail(output, pathPart, file)`；否则沿用现有 `serveFile`（mp4 + Range）。播放 URL 无查询串，`pathPart` 即原 `rawPath`，**播放行为完全不变**。
- `serveThumbnail`：取 `thumbnailGenerator.thumbnailBytes(fileId, file)`；null -> 404；否则写 `200 OK` / `Content-Type: image/jpeg` / `Content-Length` / `Cache-Control: max-age=3600` / body。缩略图很小，忽略 Range。

### 3. 改 `app/src/main/java/com/zx/homecamera/core/app/HomeCameraState.kt`（查看端状态）
`RecordingLibraryState` 新增 `val thumbnails: Map<String, android.graphics.Bitmap> = emptyMap()`。
- 用 `android.graphics.Bitmap`（非 Compose `ImageBitmap`）保持 `core/app` 不耦合 Compose；UI 层 `asImageBitmap()` 转换。复刻现有 `downloads` map 范式。

### 4. 新建 `app/src/main/java/com/zx/homecamera/network/ThumbnailLoader.kt`（查看端）
进程级单例 object，缓存跨 Activity/ViewModel 重建复用：
- `LruCache<String, Bitmap>(6MB)`，`sizeOf` 按 `byteCount` 计。
- `get(fileId): Bitmap?` 同步读缓存。
- `load(device, fileId, onResult: (Bitmap?) -> Unit)`：缓存命中即回调；否则 `ConcurrentHashMap` inFlight 去重，提交到 2 线程 daemon 执行器；`HttpURLConnection` GET `http://<host>:62003/<fileId>?thumb=1`（5s 超时），非 200 或解码失败 -> null；成功入缓存。回调在工作线程触发，由 ViewModel 用 `viewModelScope.launch` 切回主线程。
- `clear()`（可选，用于 `onCleared`）。

### 5. 改 `app/src/main/java/com/zx/homecamera/RecordingLibraryViewModel.kt`（查看端）
- 新增 `fun requestThumbnail(fileId)`：先 `ThumbnailLoader.get(fileId)` 同步命中则直接更新 state；否则 `ThumbnailLoader.load(device, fileId) { bmp -> viewModelScope.launch { 更新 _state.thumbnails } }`。用 `ThumbnailLoader` 自带执行器，**不占用** `recordingExecutor`。
- `updateThumbnail` 仅在 state 中尚无该 fileId 缩略图时写入，避免重复 copy。

### 6. 改 `app/src/main/java/com/zx/homecamera/ui/activity/RecordingLibraryActivity.kt`（查看端 UI — 两列正方形网格）
**列表区由 `LazyColumn` 改为 `LazyVerticalGrid(columns = GridCells.Fixed(2), ...)`**，`horizontalArrangement = spacedBy(10.dp)`，沿用现有 `items(state.files, key = { it.fileId })`。

每个格子内：
```
┌──────────────────┐
│                  │
│   正方形首帧预览   │  ← Modifier.fillMaxWidth().aspectRatio(1f)，圆角 8dp
│   (无图时占位▶)    │     有缩略图: Image(Crop)；无: 居中占位文字/留空 surfaceContainerHighest 背景
│                  │
├──────────────────┤
│ 14:30:00 [录制中] │  ← 时间 + 录制中/已损坏 badge
│ 大小 12.3MB       │  ← 大小（录制中显示提示语）
│ [████░░] 60%      │  ← 下载进度条（仅下载中显示）
│ [播放] [下载]      │  ← PillButton，窄一些适配半屏宽
└──────────────────┘
```
- 整格为一个 `Column` 卡片（`clip(RoundedCornerShape(12.dp))` + `background(containerColor)` + `padding`），`containerColor` 逻辑沿用现有录制中/已损坏用 `errorContainer`。
- 缩略图区：`Box(Modifier.fillMaxWidth().aspectRatio(1f).clip(RoundedCornerShape(8.dp)).background(surfaceContainerHighest))`，内有图 `Image(bitmap.asImageBitmap(), contentScale = ContentScale.Crop)`，无图居中占位。
- 每项加 `LaunchedEffect(entry.fileId) { viewModel.requestThumbnail(entry.fileId) }`（懒触发：滚入视野才请求，滚出自动取消）。
- `RecordingFileItem` 新增参数 `thumbnail: Bitmap?`，传入 `state.thumbnails[entry.fileId]`。
- 按钮区放在底部 `Row`，两按钮间 `Spacer(6.dp)`，整体可窄。
- 新增 import：`androidx.compose.foundation.Image`、`androidx.compose.foundation.lazy.grid.GridCells`、`androidx.compose.foundation.lazy.grid.LazyVerticalGrid`、`androidx.compose.foundation.lazy.grid.items`、`androidx.compose.foundation.layout.aspectRatio`、`androidx.compose.ui.graphics.asImageBitmap`、`androidx.compose.ui.layout.ContentScale`、`android.graphics.Bitmap`。移除不再需要的 `LazyColumn` import。

**注意**：`LazyVerticalGrid` 属 `androidx.compose.foundation:foundation`（material3 传递依赖），**无需新增任何依赖**。

## 边界与兼容
- 损坏 mp4 / 录制中文件（无 moov）：`ThumbnailGenerator` 返回 null -> HTTP 404 -> 占位。✓
- 旧采集端（无 `?thumb=1` 路由）：404 -> 占位，不崩溃、不影响列表/播放。✓
- 文件在列表与请求间被删：`resolveSafeFile`/非文件 -> 404 -> 占位。✓
- 旋转：读 `METADATA_KEY_VIDEO_ROTATION` 校正，与播放朝向一致。✓
- 并发同 fileId：采集端 per-fileId lock + 查看端 `inFlight` 双重去重。✓
- 播放路径（无查询串）行为不变；`RecordingEntry`/`ControlProtocol` 零改动。✓

## 测试
- `ThumbnailGenerator` 依赖真实 mp4 + `MediaMetadataRetriever`（instrumented），与无单测的 `RecordingIntegrityChecker` 同类；沿用现状，不新增 JVM 单测。
- 实现后用 android-emulator 构建运行，打开历史录像页验证：两列正方形缩略图网格、滚动懒加载、损坏项显示占位、播放/下载仍正常。

## 不做（保持最小改动面）
- 不引入 Coil/Glide 等图片库（与项目零依赖风格一致）。
- 不在录制时生成缩略图（懒加载已覆盖历史录像）。
- 不持久化缩略图到磁盘（避免与现有清理逻辑产生孤儿文件；内存缓存 + 长驻前台服务足够，重启后懒重生成）。
- 不改控制协议、不改 `RecordingEntry`、不改录制路径。
