## 问题根因

回放页 `RecordingPlaybackActivity` 的「已保存到相册」状态存在 `RecordingPlaybackState.savedToGallery`（`HomeCameraState.kt:142`），是一个纯内存 `Boolean`。`RecordingPlaybackViewModel.init()`（第33-42行）只设置播放 URL，**从不查询相册**，所以每次进入页面 `savedToGallery` 都是 `false`，状态丢失。

对比历史录像列表页：`RecordingLibraryViewModel.queryDownloadedFileIds()`（第208-229行）每次加载列表都会查询 MediaStore 的 `Movies/HomeCamera/` 目录重建「已下载」状态，命名规则是 `HomeCamera_<fileId 中 / 替换为 _>`。回放页保存相册时用的是完全相同的命名（`RecordingPlaybackViewModel.kt:80`），所以可以用同一种查询方式恢复状态。

用户已确认方案：**查询相册重建状态** + **只修复回放页**。

## 实现步骤

### 1. 新建公共工具 `GalleryDownloadStore.kt`

路径：`app/src/main/java/com/zx/homecamera/local/GalleryDownloadStore.kt`（与 `LocalData.kt` 同包，符合「本地数据」语义）。

抽取历史列表页 `queryDownloadedFileIds` 的查询逻辑为静态/单例方法：
- `fun queryDownloadedDisplayNames(context: Context): Set<String>` —— 查询 `Movies/HomeCamera/` 下所有 `DISPLAY_NAME`。
- `fun displayNameFor(fileId: String): String` —— 统一命名规则 `HomeCamera_<fileId 中 / 替换为 _>`（注意处理已带前缀的情况，与 `RecordingApiClient.galleryDisplayName` 第199-203行一致）。
- `fun isDownloaded(context: Context, fileId: String): Boolean` —— 便捷判断单个 fileId 是否已下载。

### 2. 回放页 `RecordingPlaybackViewModel`：进入时恢复状态

修改 `init()`，在设置播放 URL 后，用 `recordingExecutor` 异步查询相册，确认当前 `fileId` 是否已存在，恢复 `savedToGallery`：
```
fun init(device: CollectorDevice, fileId: String) {
    this.device = device
    val url = ...
    _state.value = _state.value.copy(
        fileId = fileId,
        playbackUrl = url,
        status = RecordingPlaybackStatus.Playing,
    )
    // 恢复「已保存到相册」状态：查询系统相册是否已存在该录像
    recordingExecutor.execute {
        val downloaded = GalleryDownloadStore.isDownloaded(getApplication(), fileId)
        viewModelScope.launch {
            // 仅在未因保存动作改变状态时更新，避免与正在进行的保存冲突
            if (!_state.value.savingToGallery && _state.value.fileId == fileId) {
                _state.value = _state.value.copy(savedToGallery = downloaded)
            }
        }
    }
}
```
查询是 IO 操作，用现有的 `recordingExecutor`（单线程）异步执行，与 `savePlaybackToGallery` 的线程模型一致，不阻塞主线程。增加 `fileId` 一致性检查，防止用户快速操作时状态错乱。

### 3. 历史列表页 `RecordingLibraryViewModel`：复用公共工具（消除重复）

将 `queryDownloadedFileIds`（第208-229行）改写为调用 `GalleryDownloadStore.queryDownloadedDisplayNames` + `displayNameFor`，行为完全不变（依然返回已下载 fileId 集合），仅消除重复代码，让两处共享同一份命名/查询逻辑。

### 4. 验证

- 编译通过（gradle build）。
- 行为验证（无需自动测试，逻辑上）：进入回放页 → 保存到相册 → 退出 → 重新进入 → 按钮应显示「已保存到相册」且不可点击。若相册中已无该文件（用户在系统相册删除），状态自动回到「保存到相册」可点击，符合「查询相册重建」方案语义。

## 影响范围

- 新增：`local/GalleryDownloadStore.kt`
- 修改：`RecordingPlaybackViewModel.kt`（init 恢复状态）、`RecordingLibraryViewModel.kt`（复用工具，行为不变）
- 不动：UI 层、数据模型、`RecordingApiClient`、`RecordingPlaybackActivity`（按钮逻辑已正确，状态来自 ViewModel 即可）

## 风险

- 低。查询相册是只读操作，权限上 Android 10+ 读取 `Movies/HomeCamera/` 无需额外权限（与历史列表页一致）。
- `savedToGallery` 恢复有极小窗口与 `savePlaybackToGallery` 并发，通过 `savingToGallery` 和 `fileId` 一致性检查规避。
