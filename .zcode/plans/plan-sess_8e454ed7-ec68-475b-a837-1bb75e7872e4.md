# 录像在线播放：HTTP Range 服务器 + 进度条

## 问题根因

当前录像播放是"先完整下载到内部缓存 -> VideoView 播本地文件"。大文件因内部存储不足、传输截断无校验、moov 在文件尾导致播放失败；且 VideoView 无 MediaController 无进度条。

## 方案

采集端新增固定端口的轻量 HTTP 服务器（支持 Range 请求），客户端 VideoView 直接播 `http://host:62003/<fileId>`。MediaPlayer 原生支持 HTTP Range：自动先请求文件尾的 moov，再按需分段请求 mdat，实现边下边播 + 拖拽进度条。彻底去掉"下载完整文件"环节。

## 改动

### 1. 采集端 - 新增 HTTP Range 服务器

**新增 `service/RecordingHttpServer.kt`**：
- 固定端口 `HTTP_PORT = 62003`，`ServerSocket(62003)` 常驻监听
- 每个连接线程解析 HTTP 请求行（`GET /<fileId> HTTP/1.1`）+ `Range:` 头
- 路径穿越校验复用 `RecordingTransferServer.resolveSafeFile` 逻辑（`..` 拦截 + canonicalPath 校验）
- 响应：
  - 有 Range：`206 Partial Content` + `Content-Range: bytes start-end/total` + `Content-Length`
  - 无 Range：`200 OK` + `Content-Length`（整文件）
  - `Accept-Ranges: bytes` 始终返回
  - `Content-Type: video/mp4`
- 只读文件指定字节范围写入 socket 输出流（`RandomAccessFile` + `seek`）
- 生命周期：`start()` 启动监听线程，`stop()` 关闭 server socket + executor

**`CollectorForegroundService.kt`**：
- 新增 `recordingHttpServer` 字段 + 独立 executor
- `startCollector` 中启动 HTTP 服务器
- `releaseCollectorResources` 中 `stop()` 并置 null
- companion 新增 `HTTP_PORT = 62003`
- `handleOpenRecording` / `RecordingTransferServer`：保留不动（下载到相册改走 HTTP，但为降低风险先不删旧路径，后续清理）

### 2. 客户端 - 在线播放

**`RecordingPlaybackViewModel.kt`**：
- `loadRecordingForPlayback` 改为：不再调 `downloadToCache`，直接构造 `http://<host>:62003/<fileId>` 存入 state（新增 `playbackUrl: String?` 字段替代 `cachedFile`），状态置 `Playing`
- `savePlaybackToGallery` 改为：从 `http://<host>:62003/<fileId>` HTTP GET 整文件下载到相册（用 `HttpURLConnection`），不再依赖 cachedFile

**`HomeCameraState.kt`**：
- `RecordingPlaybackState`：`cachedFile: File?` 改为 `playbackUrl: String?`

**`RecordingPlaybackActivity.kt`**：
- VideoView：`setVideoURI(Uri.parse(state.playbackUrl))` 替代 `Uri.fromFile(cachedFile)`
- 挂载 `MediaController`：`MediaController(context).apply { setMediaPlayer(videoView); setAnchorView(videoView) }`，点屏幕显示进度条/拖拽/播放暂停
- `setOnErrorListener`：返回 true 消费错误，置 Error 状态显示提示（避免黑屏无反馈）
- `setOnPreparedListener`：保留 `isLooping = false`

### 3. Manifest - 放行 cleartext

**`AndroidManifest.xml`**：
- `<application>` 加 `android:usesCleartextTraffic="true"`（局域网 HTTP 必需，targetSdk 36 默认禁明文）

### 4. 下载到相册改造

**`RecordingApiClient.kt`**：
- 新增 `downloadToGallery(context, host, httpPort, fileId, onProgress)`：HTTP GET 整文件到 MediaStore
- 旧的 `downloadToCache` / `openTransfer` / TCP `downloadToGallery` 保留但播放路径不再使用（降低删除风险）

## 不改动
- `ControlProtocol` 协议不变
- `RecordingTransferServer` 暂保留（旧路径兜底，后续可清理）
- 实时预览链路不变
- 录像存储/分段/旋转元数据不变

## 验证
- 编译通过
- 实机：点播录像应即时开始播放（无需等下载完成）；点屏幕出现进度条可拖拽；保存到相册正常；大文件不再失败
