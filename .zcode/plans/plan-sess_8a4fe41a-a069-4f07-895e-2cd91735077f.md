## 下载队列改造方案

### 目标
历史录像下载改为「一次只下载一个，多个点击进入队列顺序执行，可随时取消（当前下载中或排队中均可取消）」。

### 现状
- `RecordingLibraryState` 只有一个 `downloadingFileId: String?` + `downloadProgress: Float`，无法表达队列。
- `RecordingLibraryViewModel.downloadRecordingToGallery()` 直接覆盖 `downloadingFileId`，第二次点击会挤掉第一次。
- 下载与列表加载共用同一个 `recordingExecutor` 单线程池，下载会阻塞刷新。
- `RecordingApiClient.cancel()` 关闭当前传输 socket 即可中断下载（无需改动）。
- 取消/下载只影响库页面，与 Playback 路径无关。

### 改动文件（3 个）

#### 1. `core/app/HomeCameraState.kt`
新增下载状态类型，并把 `RecordingLibraryState` 的单文件下载字段替换为 map：

```kotlin
enum class DownloadStatus { Queued, Downloading }

data class DownloadTaskState(
    val status: DownloadStatus,
    val progress: Float,
)

data class RecordingLibraryState(
    val status: RecordingLibraryStatus = RecordingLibraryStatus.Loading,
    val dates: List<String> = emptyList(),
    val selectedDate: String? = null,
    val files: List<RecordingEntry> = emptyList(),
    val downloads: Map<String, DownloadTaskState> = emptyMap(),   // 新：fileId -> 任务状态
    val downloadedFileIds: Set<String> = emptySet(),
    val errorMessage: String? = null,
)
```
删除 `downloadingFileId` 与 `downloadProgress`（已确认仅库页面引用）。

#### 2. `RecordingLibraryViewModel.kt`
- 新增独立 `downloadExecutor = Executors.newSingleThreadExecutor()`，专门串行执行下载，不再阻塞列表/刷新（顺带修复「下载阻塞刷新」的小问题）。
- 用 `queueLock` 守护的 `ArrayDeque<String>` 维护 FIFO 队列，以及 `currentDownloadFileId`、`downloadLoopActive`。
- `downloadRecordingToGallery(fileId)`（UI 线程调用）：
  - 若已在队列/下载中/已下载 → 忽略。
  - 否则入队，置 `downloads[fileId] = (Queued, 0f)`，确保下载循环在跑。
- 下载循环（在 `downloadExecutor` 上）：从队首取 fileId → 置 Downloading → 调 `recordingApi.downloadToGallery(...)`（沿用现有进度回调与 MediaStore 写入，无需改 Client）→ 成功则加入 `downloadedFileIds`，失败/取消则仅移除该任务状态；循环继续处理下一个。
- `cancelDownload(fileId)`（UI 线程调用）：
  - 若 fileId 是当前下载 → `recordingApi.cancel()` 关闭 socket 中断它，循环捕获异常后自动进入下一个。
  - 若 fileId 在队列中（未开始）→ 直接从 `ArrayDeque` 移除。
  - 清除该 fileId 的下载状态。
- 状态更新沿用文件现有风格 `viewModelScope.launch { _state.value = _state.value.copy(...) }`（Main 单线程，读-改-写安全，与现有进度回调一致）。
- `onCleared()` 增加 `downloadExecutor.shutdownNow()` 与 `recordingApi.cancel()`。
- `RecordingApiClient` 不改动：`cancel()` 仍中断当前下载，`downloadToGallery` 仍按 fileId 逐个执行。

#### 3. `ui/activity/RecordingLibraryActivity.kt`
- 列表项改为按 fileId 查 `state.downloads[entry.fileId]` 取任务状态与进度。
- `RecordingFileItem` 参数：`isDownloading/isQueued` 由 `DownloadStatus?` 派生。
- 下载按钮文案与行为：
  - Downloading → 「停止」（取消当前下载）
  - Queued → 「取消」（移出队列）
  - 已下载 → 「已下载」（禁用）
  - 其他 → 「下载」
- `onCancel = { viewModel.cancelDownload(entry.fileId) }`（按 fileId 取消）。
- 进度条仅 Downloading 时显示；Queued 时在副标题处显示「排队中」小灰字，给用户明确反馈。

### 行为校验
- 下载 A 中点 B → A 继续，B 标记「排队中/取消」，A 完成后自动开始 B。✓
- 取消排队中的 B → 从队列移除，按钮回到「下载」。✓
- 取消下载中的 A → 中断 socket，A 回到「下载」，队列下一个自动开始。✓
- 已下载文件按钮禁用，不会重复入队。✓
- VM 销毁时关闭执行器并中断当前 socket（与现有生命周期一致，不引入后台服务）。✓

### 不在范围
- 后台保活下载（前台服务/WorkManager）、断点续传、Playback 页 HTTP 保存路径——均不改。

### 验证
实现后用 `assembleDebug` 编译确认无错误。
